# ADR 0001: Declarations are authority; observations are evidence

- **Status**: accepted
- **Scope**: `go.putnami.dev/protocol/architecture`

## Context

A workspace needs executable domain boundaries without making one central
matrix, one shared `Workspace` object, or one Markdown document the source of
truth. Local copies must be allowed for availability and performance while one
explicit authority owns every fact. Existing project dependencies must be
ratcheted, neither breaking adoption nor being silently declared valid.

## Decision

### 1. Each domain owns one manifest

`putnami.architecture.json` declares the domain, its project mapping, semantic
ownership, exports, and imports. A producer owns facts and compatibility. A
consumer owns its access mode, minimized fact set, local model, consistency, and
implementation bindings. The global graph is generated by joining manifests.

### 2. A DARC import references an export

The export is reusable producer authority; the import is the consumer-specific
access contract. Validation requires the producer domain and export to exist,
the mode to be allowed, and every imported fact to be exposed. Each domain
authors its own half; neither mirrors the whole record.

### 3. Structural permissions are exact bindings

A non-planned import may carry exact `project-dependency` bindings, and the
detector compares project IDs, not domains: one legitimate relation must not
authorize every future dependency between two domains. A planned import cannot
carry bindings, so a target never masquerades as as-built reality.

### 4. Facts carry classification unless the export is reference-only

Every export fact carries authority and identity. `classification` and
`personalData` are both required unless `reference` is the export's sole allowed
mode, in which case both may be omitted: a reference names an authority boundary
and moves no data. An export that allows `query`, `snapshot`, `projection`, or
`command`, alone or with `reference`, requires both fields on every fact.
Supplying only one of the two is invalid.

### 5. Projection guarantees are part of the wire

A projection is valid only when bootstrap, updates, ordering, idempotency,
freshness, safe failure, provenance, observation time, one writer, rebuild, and
deletion are explicit. Projected and local fields are disjoint. The protocol
does not prescribe a generic workspace DTO.

### 6. Debt is not permission

The adoption baseline and waivers hold finding IDs plus accountability metadata
and contribute no graph edge. New findings fail; known debt warns. The baseline
is shrink-only against the selected Git revision, and stale baseline or waiver
entries fail.

### 7. Detector coverage is part of every snapshot

Exact Putnami project dependencies are enforced for projects mapped to domains.
The database detector reports `not-detected`. Committed capability evidence
raises `domainAccess`, and HTTP or event coverage for an evidenced API or event
transport, to `framework-evidence` at most; without evidence they report
`not-detected`. A declared transport creates no observed evidence, and no report
claims enforcement it did not perform.

## Rejected alternatives

- **One central domain matrix.** It duplicates ownership and makes every domain
  change contend on one inventory.
- **A shared `Workspace` schema.** A stable reference, a local projection, local
  configuration, and local state have different owners and lifecycles.
- **Events as the default transport.** Mode and consistency determine transport.
- **Match observed dependencies by domain pair.** One DARC would silently
  authorize every further project edge.
- **Baseline entries as declared edges.** Debt would become permanent permission.
- **Rules in product-specific configuration.** CLI, CI, agents, and other
  workspaces must share one protocol.
- **A database per domain.** Logical authority is the invariant; physical
  topology is an independent choice.
- **Default `public` / `none` on reference-only facts.** It adds no policy
  information and weakens strict parsing.

## Consequences

A workspace adopts incrementally: map some domains, baseline existing
violations once, and add planned DARC targets without claiming their transports
are live. New detectors widen observed evidence and coverage without changing
the meaning of existing manifests.
