# ADR 0001: Committed requirements are rendered as a formatter fixed point

- **Status**: accepted
- **Scope**: `go.putnami.dev/protocol/infra` (`protocols/infra`)

## Context

`<project>/infra/requirements.json` is generated by framework producers during
the build and committed, where the repository JSON formatter also owns it. If
the generator and the formatter disagree on layout, each undoes the other: noisy
diffs, dirty CI worktrees, and cache-key churn on the committed deployability
marker, which must change only when a requirement changes.

## Decision

`SyncGeneratedRequirements` renders the committed file through
`marshalCommitted` (`committed_format.go`), which reproduces the exact shape the
formatter (Biome, `expand: "auto"`) leaves untouched:

- objects, and arrays containing objects, stay expanded, one element per line;
- a scalar-only array (`schemas`, `secrets`, an events topic list) collapses
  onto one line when it fits the print width, counting indentation, the
  `"<key>": ` prefix, and any trailing comma, and expands otherwise;
- indentation is two spaces, HTML escaping is off, and the file ends with a
  newline.

`committedLineWidth` (120) mirrors the formatter's `json.formatter.lineWidth`
and changes with it. The generator removes a stale committed file when no
producer declares requirements. The uncommitted per-producer fragments under
`.gen/infra/` stay in `MarshalIndent` form.

## Rejected alternatives

- **A per-file formatter override.** It hides one committed file from the
  formatting rules, in every consumer repository.
- **Shell out to the formatter before comparing.** It couples a protocol write
  to a language toolchain.
- **Stop committing the file.** The committed marker makes deployability
  reviewable and lets deploy activation work from a clean checkout.
- **Reformat in CI after generation.** A fix-up after the cache key is computed
  is a determinism hazard.

## Consequences

- The Go constant and the formatter config must stay in sync; a width change
  that forgets the constant reintroduces churn.
- The fit check relies on ASCII resource names (the schema restricts them), so
  byte length equals display width.
- `putnami lint` never reflows the file, the generator never re-churns it, and a
  diff on it always means a requirement changed.
